# Foundgine cross-language conformance

A warrant signed by the C# implementation must verify in Java and vice versa, so both must produce identical
canonical bytes. `warrant-canonicalization.json` holds the reference vectors (`spec: warrant-canonical-form-v1`),
generated by `tools/generate_warrant_vectors.py` (an independent third implementation, Python).

Files:
- `warrant-canonicalization.json` - canonical bytes and digest (`WarrantCanonicalizationConformance*`).
- `delegation-scenarios.json` - attenuation and chain validation, 32 scenarios (`WarrantDelegationConformance*`). Each
  carries the expected exception message (identical in both runtimes) or `null`, every warrant's digest, and the chain
  digest for valid chains. `$digest:N` placeholders are resolved by the generator, never by the runners.

- `warrant-signatures.json` - RSA PKCS#1 v1.5/SHA-256 is deterministic, so each valid case carries the exact signature an
  independent implementation (Python `cryptography`) produced; signers must reproduce it byte for byte and verifiers must
  accept/reject all 19 cases with the same message (`WarrantSignatureConformance*`). The embedded key pairs are TEST-ONLY.
  Keep them: regenerating with new keys changes every signature (`FOUNDGINE_REGENERATE_KEYS=1`).

Run: `dotnet test --filter WarrantCanonicalizationConformance` / `--filter WarrantDelegationConformance` / `--filter WarrantSignatureConformance` and
`mvn -pl foundgine-core test -Dtest='Warrant*ConformanceTest'`.
Never edit the JSON by hand; change the generator and regenerate.

## Canonical form v1
- UTF-8, no whitespace, property order exactly as in the vectors.
- Strings: escape only `"` `\` `\n` `\r` `\t` `\b` `\f` and other C0 controls as `\u00xx` (lowercase hex). Everything
  else (non-ASCII, astral characters, `+ & < > ' ``, DEL) is emitted raw. Unpaired surrogates are an error.
- Ordering: UTF-16 code units (.NET `StringComparer.Ordinal`, Java `String.compareTo`), *not* code points.
  Grants sort by capability, operation, then scopes joined with U+001F. List fields are blank-filtered, de-duplicated
  and sorted; `delegationPath` keeps its order.
- Timestamps: UTC, `yyyy-MM-ddTHH:mm:ss.fffffffZ` (seven digits, literal `Z`).
- `maxResults` is a plain integer; `maxAmount` is the plain decimal with its scale preserved (`100.50` stays `100.50`).
  Absent values are `null`.

## Resolved divergences and notes
- Time precision: resolved. Java `SecurityWarrant` truncates `issuedAt`/`expiresAt` to 100 ns on construction (the
  canonical resolution and .NET tick size), so digests and comparisons agree. Unit-tested in Java only.
- Blank strings: resolved. Both runtimes use one explicit rule (`WarrantText`): empty, or only U+0009-U+000D and U+0020.
  Other Unicode spaces (U+00A0, U+2003, U+0085, U+001C...) are kept as real values. Previously .NET dropped NBSP-only
  and Java dropped U+001C-U+001F-only scope strings. Covered by a vector. Only grant/constraint normalization uses it;
  validation checks elsewhere (trust stores, replay store) still use the platform predicate.
- Digests of existing C# warrants whose strings contained `+ & < > ' `` or non-ASCII characters change, because the old
  C# serializer escaped them as `\uXXXX`. Re-issue such warrants; warrants with plain ASCII values are unaffected.
