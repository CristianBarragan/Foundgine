# Foundgine Migrations (Java)

`foundgine-migrations` derives a PostgreSQL-oriented schema from a `FoundgineModel` metadata
registry, compares it with a committed JSON snapshot, and writes versioned Flyway migrations,
rollback SQL and migration history.

## CLI

The CLI is `com.foundgine.migrations.MigrationsCli`. Configure a public no-argument
`FoundgineModel` class in `foundgine-migrations.properties`:

```properties
model=com.example.persistence.ApplicationModel
jdbc.url=jdbc:postgresql://localhost:5432/application
jdbc.user=application
jdbc.password=change-me
demo.dir=src/main/resources/db/demo
```

Run it from a Maven project that has the module on its classpath:

```bash
migrations add InitialCreate
migrations list
migrations has-pending-model-changes
migrations script
database update
database status
migrations remove
```

The supported command set is `migrations add <Name>`, `migrations remove [--force]`,
`migrations list`, `migrations script [fromVersion]`,
`migrations has-pending-model-changes`, `database update [targetVersion]` and
`database status`. CLI options can override project/model/connection configuration; the sample
wrappers demonstrate invocation through Maven.

## PostgreSQL schema model and SQL support

The migration schema snapshot and PostgreSQL SQL generator represent:

- Tables, schema-qualified names, columns, primary keys and ordinary/unique indexes.
- Column defaults expressed as PostgreSQL SQL and identity columns (`GENERATED ALWAYS` or
  `GENERATED BY DEFAULT`). Identity generation can be created with a table or added as a column;
  changing an existing column's identity strategy is rejected for a hand-written migration.
- Named foreign keys with composite column pairs and `ON DELETE` / `ON UPDATE` actions.
- Named CHECK constraints.
- PostgreSQL extensions, including `pg_trgm`.
- Index access methods such as `btree` and `gin`, with an optional operator class such as
  `gin_trgm_ops`.

The existing three- and four-argument schema constructors remain available, and older JSON
snapshots that omit the new fields load with empty/null defaults. The differ orders extension
creation before dependent objects, table creation before foreign keys, and constraint removal
before dependent table/column removal. Rollback generation restores foreign keys after recreating
all dropped tables.

**Fluent model integration:** `SchemaBuilder.fromMetadata(MetadataRegistry)` now carries column
identity generation and default expressions, named single- and composite-column foreign keys (including
referential actions), named CHECK constraints, PostgreSQL index methods/operator classes, and
required extensions from the core fluent persistence metadata. partial/expression indexes, and other database objects outside these descriptors still require
explicit migration SQL. The generated SQL must be reviewed and tested against the target PostgreSQL
version before replacing handwritten migrations.

Default expressions and CHECK expressions are trusted, model-authored PostgreSQL SQL fragments;
they are not parsed or sanitized. An index operator class, when specified, is applied to each
column in that index. Review these fragments and generated SQL before applying migrations.

The generator does not infer renames, PostgreSQL extension dependencies, arbitrary expression or
partial indexes, triggers, views, generated columns, or safe data backfills. Unsupported or
ambiguous changes should remain hand-written. Review forward and rollback SQL before applying it.
Do not use `--force` to remove an applied migration unless database history has deliberately been
repaired.
