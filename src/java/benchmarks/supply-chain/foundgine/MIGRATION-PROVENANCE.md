# Java Foundgine arm migration provenance

The runtime migration is the versioned SQL generated by the repository's
`foundgine-migrations` tool from the SupplyChain fluent model and packaged in
the `foundgine-sample-supply-chain` reactor dependency at
`src/main/resources/db/migration/V20261114161434__InitialCreate.sql`.

This application deliberately does not copy that resource into its own JAR:
Flyway discovers the single migration from the sample dependency on the
runtime classpath. The baseline arm instead owns an independently authored
`V1__baseline.sql`. Both use Flyway to apply DDL; Hibernate schema generation
is not used for the Foundgine arm.

Regenerate the Foundgine migration through `migrations.sh` before release and
verify the Flyway history on a clean PostgreSQL database. The presence of the
checked-in generated artifact is not evidence that a clean runtime migration
has passed.

The shared benchmark security infrastructure also creates `foundgine_warrant_revocation_epoch` in this arm database. The Foundgine arm uses the provider migrator; the baseline creates the same table from its Flyway migration and idempotent JDBC initializer. This table is included in schema-parity output and must remain structurally identical between the two Java arms.
